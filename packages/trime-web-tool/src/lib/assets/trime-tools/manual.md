基於[倉輸入法·工具](https://lost-melody.github.io/hamster-tools/)做了大量修改，符合同文輸入法的設計工具，可直接編輯並導出 `xxx.trime.yaml`。

### 功能區

一份主題 = **一份樣式（主題設定）** + **多張鍵盤** + **多份配色**。

- 頂部操作欄
  - 導出: 導入或導出完整 `xxx.trime.yaml`；可單獨導出／複製 style、配色、鍵盤、preedit、window、tool_bar、後備顔色、主題鍵；「重置」會回到一份預設配色 + 一張預設 26 鍵，並清掉其餘鍵盤
  - 模板: 點鍵盤模板會覆蓋**目前這張鍵盤**的佈局（代碼與顯示名稱保留）；點配色模板會覆蓋**目前這份配色**的顔色（代碼、名稱、深淺色指向保留）
  - 檔案: 瀏覽器暫存整份主題（共 10 格）。點删除／覆蓋／加載後需再等約 2 秒確認，期間可再點取消。這不是長期備份，長期請用導出
  - 操作: 對目前鍵盤的扁平按鍵列表插入、删除、複製末鍵、強制換行、統一鍵寛、功能鍵標記
- 配色／鍵盤列表: 右側兩列縮圖；點選要編輯的那一份。鍵盤縮圖可拖曳，順序就是切換鍵盤的輪換順序。最後一份配色或最後一張鍵盤不能删
- 預覽區: 依同文折行規則與 fallback 配色顯示，僅供參考。下方「隱藏角標／横屏／置頂」只影響本頁預覽，不會寫進 yaml
- 主題（左側，可收合）: 整份主題共用的 `style`、候選區、字體、Enter 標籤、預編輯、候選窗口、工具欄、主題鍵、後備顔色
- 編輯頁籤
  - 按鍵: 觸發槽（單按／長按／滑動等）、標籤、角標、鍵寛、單鍵配色覆蓋。`functional`、`repeatable`、`preview` 要設在「主題鍵」，同文 3.3.11 不從單鍵項目讀取
  - 配色: `preset_color_schemes` 各組顔色；可寫實色、組標籤引用，部分欄位可寫圖片檔名
  - 鍵盤: 這一張鍵盤自己的代碼、中／英、間距、鍵高、圓角、鍵盤高度等



### 導入與導出

- 導入時按段落合併: `style`、`preedit`、`window`、`tool_bar`、`fallback_colors`、`preset_color_schemes`、`preset_keys`、`preset_keyboards`
- 同檔案内的 `__include`、`import_preset`、`__patch` 會嘗試展開；指向外部檔的 `__include` 會略過並提示
- 導出完整主題爲 `xxx.trime.yaml`。鍵盤切換順序寫入 `style.keyboards`（與右側鍵盤縮圖順序相同，不可在文字框裡手改）
- 某欄位若留空、導出時省略: 同文會用內建預設或 `fallback_colors` 鏈去補，不一定報錯，但畫面可能跟預覽不一樣



### 安裝到同文輸入法

- 將導出的 `主題名.trime.yaml` 放到 Android 同文的 Rime 用戶資料夾（通常爲 `rime/` 或同文設定中顯示的用戶目錄）
- 若配色用了圖片，把圖檔放到主題裡設定的「背景目錄」
- 在同文中執行「部署」，再於主題／配色設定中選取



### 使用邏輯（常見疑問）

- 樣式和鍵盤是 1 對 1 嗎？
  > 不是。一份主題只有一份樣式（候選欄、字號、字體、工具欄、後備顔色、主題鍵、跟隨系統等），鍵盤可以有很多張。右側「+」加的是鍵盤，不是新樣式
- 鍵寛、間距、圓角、鍵盤高度寫在哪？
  > 寫在每一張鍵盤上。不同鍵盤可以有不同尺寸。舊檔若只寫在 `style` 裡，導入時會補到鍵盤上
- 候選區高度、字號、註釋位置、內距、字體檔名在哪？
  > 左側「主題」→「候選、字號與邊距」「字體檔名」「功能」裡的註釋位置。候選那一行的顔色在「配色」頁籤
- 鍵盤代碼（如 qwerty、symbols、pinyin）是什麼？
  > 同文用這串 id 識別鍵盤，內建名稱可下拉選，也可自己輸入。切換鍵盤按鍵、`ascii_keyboard` 都是填這個代碼
- 「一打開鍵盤／換 App 時／在中文切換到英文時用」是什麼？
  > 一打開: 每次叫出這張鍵盤時先中文、先英文，或沿用上一次中／英
  >
  > `ascii_mode` 不能靠省略表示中文：同文 3.3.11 省略時預設爲 `1`（西文）。編輯器會明確導出 `0` 或 `1`
  >
  > 換 App 時「記得上一個鍵盤」: 換應用後仍停在你正在用的那張；「永遠用預設」則回到主題預設鍵盤
  >
  > 切到英文時用: 可改用另一張鍵盤（例如英文 26 鍵）。空白＝還是這張，只改中／英狀態（空格上的方案名、中文鍵等）
- 鍵盤已經是「美式國際／英文佈局」，爲什麼還在打中文？
  > 佈局名稱（如 `us_intl`）只決定鍵位，**不決定** Rime 中／英。打不打拼音看這張鍵盤的 `ascii_mode`
  >
  > **編輯器**：選中該鍵盤 →「一打開鍵盤」選「每次都先打英文」。會寫成 `ascii_mode: 1` 與 `reset_ascii_mode: true`（每次切進來都強制西文，不被上次記住的中文狀態蓋掉）
  >
  > **YAML**：
  >
  > ```yaml
  > us_intl:
  >   ascii_mode: 1
  >   reset_ascii_mode: true
  > ```
  >
  > 官方預設 `trime.yaml` 的 `us_intl` 本身已是 `ascii_mode: 1`。自己做的主題若誤設成 `0`，鍵位再像英文也會出中文候選。改完須重新導出、部署並選對主題
- 怎麼做「大寫鎖定／Caps」？`long_click: Caps_Lock` 爲什麼沒用？
  > 軟鍵盤上的 Caps 不是 Android `Caps_Lock` 硬體鍵。要用主題鍵：`send: Shift_L` 加上 `shift_lock`（`long`／`ascii_long`／`click`），再讓 Shift 的長按（或單按）指向它
  >
  > **編輯器**：左側「主題」→「主題鍵」新增例如 `Shift_Lock`，`send` 填 `Shift_L`，`shift_lock` 填 `long`；再到該鍵盤的 Shift 鍵，長按槽填 `Shift_Lock`
  >
  > **YAML**：
  >
  > ```yaml
  > preset_keys:
  >   Shift_Lock:
  >     label: ⇧
  >     send: Shift_L
  >     shift_lock: long
  > # 鍵上：
  > - { click: Shift_L, long_click: Shift_Lock }
  > ```
  >
  > `shift_lock` 含義（同文註釋）：`ascii_long`＝西文長按鎖定、中文單按鎖定；`long`＝長按鎖定；`click`＝單按鎖定
  >
  > **官方預設主題**：已有 `Shift_L: { send: Shift_L, shift_lock: ascii_long }`，主鍵盤／`us_intl` 多半只寫 `click: Shift_L`，**沒有**另備 `Shift_Lock`／`Caps_Lock` 這類「專用大寫鎖定」主題鍵，也沒有把長按設成鎖定。若要明確的長按 Caps，需自己加主題鍵（需求常見，但預設主題沒拆出來）
- 配色代碼是 dark／light 嗎？要跟隨系統會變成兩套配色嗎？
  > 配色代碼就是這份方案的 id（不一定叫 dark／light）。跟隨系統時，是在已有的多份配色裡指定哪份當深色、哪份當淺色，寫進各方案的 `dark_scheme`／`light_scheme`。只有一份配色時不能跟隨系統
- 配色可以當背景圖嗎？爲什麼有的模板看起來很像、字又看不到？
  > 部分顔色欄可改成「圖片」並填檔名，目錄在主題的「背景目錄」。本站預覽／縮圖只畫實色，不會顯示圖檔。內建模板有幾套色相接近但不是同一份；若字色接近底色，縮圖會用按鍵高亮色當名稱底，避免看不見字
- 「額外顔色鍵」是什麼？
  > 配色裡除了 `key_back_color` 這類內建欄位外，你自己加的鍵名（同文常叫組標籤）。可設實色、引用另一個鍵，或部分欄位用圖片檔名。其他顔色可改「引用」指到它，方便多處共用同一色。若導入的主題裡有內建清單以外的鍵，也會出現在這裡
- 套用模板會不會改掉代碼和名稱？
  > 不會。只改目前這張鍵盤的鍵位，或目前這份配色的顔色
- 爲什麼不能把最後一個配色／鍵盤删掉？
  > 主題至少要各留一份。新建或重置也是一份預設 26 鍵 + 一份預設配色
- 預覽下面的「隱藏角標」和按鍵裡的「隱藏上方長按符號」差在哪？
  > 預覽下方那顆只暫時藏角標，方便對畫面，不會寫進 yaml。按鍵裡逐顆勾選會把該鍵 `label_symbol` 設成空白，長按仍在
- 主題「功能」裡「隱藏鍵面上方長按符號」會怎樣？
  > 會立刻把所有鍵盤的每顆鍵都打上空白角標。導出或儲存時寫 `label_symbol: " "`，並在同一行加註釋 `orig_label_symbol` 記下原本的角標；取消勾選或之後導入這份檔，會依註釋還原。同文執行時不讀這則註釋，只看空白角標
- 手機上鍵面出現 select／cut／copy 疊在字母上？
  > 沒寫 `label_symbol` 時，同文會把 `long_click` 的主題鍵標籤（如 `select_all`、`cut`）畫成角標。鍵高約 32 時若 `key_symbol_offset_y` 設到 10+，角標會落到主字位置。修法：把角標偏移改小（建議 0–2），並對多字長按鍵設空白角標；編輯器「操作」裡有「隱藏多字長按角標」
- `label` 可以寫 ⌫、⇧ 這種 Unicode 嗎？要不要跳脫？
  > 可以，一般不必跳脫；YAML 遇到 `:`、`#`、開頭特殊字元時導出會自動加引號。同文會用 `key_font` 畫這些字，字型檔要真的有該字形（主題寫了 `symbol.ttf`／`label.ttf` 就要放到用戶目錄）。另外：西文模式或該鍵有西文槽時，同文可能改顯示主題鍵標籤而忽略自訂 `label`。圖示字型另可用 `ic@名稱` 前綴
- 按鍵列表爲什麼不是一排一排填？
  > 同文是扁平 `keys` 列表，用鍵寛加總自動折行。需要提前換行時，插入 `click: ""` 的強制換行鍵
- 主題鍵、後備顔色是什麼？
  > 主題鍵: 主題裡具名的按鍵配方（如 Return、Shift），鍵盤上可引用這些 id
  >
  > 所謂「同文內置」其實定義在預設的 `trime.yaml`，切換到另一份獨立主題時不會自動合併。完整導出會一併帶上這些定義，否則 `Keyboard_number`、`Mode_switch` 等名稱可能只剩普通按鍵碼或無作用。`select` 填目標鍵盤代碼，不是本主題鍵 id
  >
  > 同文 3.3.11 的字體欄位是 YAML 清單；編輯器的字體框可用逗號輸入多個檔名，導出時會轉成清單。按鍵提示使用 `popup_*`，舊版 `preview_*` 只在導入時作相容轉換
  >
  > 後備顔色: 配色沒寫到的欄位，按同文 fallback 鏈去補
- 改了設定預覽沒動？
  > 一般輸入／下拉會即時重繪。鍵盤顯示名稱改完後，右側縮圖也會跟著改
- 作者單身嗎？
  > 對，單身
